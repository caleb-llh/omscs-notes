# GPU Architecture and Programming: Course Overview

## Introduction
The breakdown of Dennard Scaling and the onset of the "Power Wall" forced a fundamental shift in computer architecture. As traditional CPUs reached their physical limits for sequential execution frequency, the industry turned to massively parallel architectures to sustain performance scaling. 

This course explores the transition from latency-optimized processors (CPUs) to throughput-optimized processors (GPUs). Rather than relying on deep caches and complex control logic to execute a single thread as quickly as possible, GPUs utilize thousands of simpler cores to execute millions of threads concurrently. By the end of this course, you will understand the hardware realities of modern GPUs, the programming models required to harness them, and the architectural innovations driving the modern artificial intelligence boom.

## Core Themes and Conceptual Framework

### 1. The Paradigm of Throughput Computing (Modules 1-4)
Traditional CPU programming is bound by Amdahl's Law, which warns that sequential bottlenecks limit the maximum possible speedup of a program. GPU programming is instead governed by **Gustafson's Law**: as compute capacity grows, we do not simply solve the same problem faster; we solve significantly larger problems. You will explore the foundational tradeoff between CPUs (sacrificing massive parallelism to guarantee low latency and precise exceptions for unpredictable tasks) and GPUs (sacrificing complex control logic for massive throughput on repetitive tasks).

You will learn how GPUs achieve this massive throughput by utilizing **zero-overhead context switching**. Unlike a CPU—which relies on Out-of-Order execution, branch prediction, and costly OS-managed context switches (saving to a PCB)—a GPU hides latency through sheer concurrency via hardware-managed multiple PCs and register sets. When one group of threads stalls waiting for data, the hardware instantly swaps in another group, keeping the computational engines continuously fed. You will explore how APIs like CUDA map this concurrency directly to physical hardware via the Thread Block and Grid hierarchy, distinguishing between **Data Decomposition** (operating identically on different data segments) and Task Decomposition, and separating the **SPMD** software abstraction from the **SIMT** hardware execution model.

This section also introduces fundamental tradeoffs in memory and hardware design. You will explore **Shared vs. Distributed Memory** models (OpenMP vs. MPI), the tradeoffs of **Static vs. Dynamic Scheduling** in OpenMP, and the surface-to-volume ratio optimization required for handling halo regions in **Stencil Operations** (where communicating boundary data adds network overhead). At the hardware level, you will analyze the tradeoff between area and bandwidth using **Register Banks** (and the resulting **Bank Conflicts**), the role of **Scoreboarding** (which in GPUs manages dependencies across massive thread counts rather than single-thread Out-of-Order execution), and how **Memory Coalescing** dictates data structure choices (trading intuitive Array of Structures for performant Structure of Arrays). Finally, you will explore the **Bulk Synchronous Parallel (BSP)** pattern and evaluate **Occupancy**—learning why achieving 100% occupancy is not always the optimal path to minimizing execution time if lower occupancy yields better cache hit rates.

### 2. Managing the SIMT Execution Model (Modules 5-6)
To maximize silicon area dedicated to pure computation, GPUs group threads into "Warps" that execute in lock-step, following a Single Instruction, Multiple Threads (SIMT) model. 

This architectural choice introduces a unique challenge: **Warp Divergence**. You will explore what happens when threads within a warp take different conditional paths (e.g., an `if-else` statement). The course details how the hardware utilizes a **SIMT Stack** (pushing alternative PCs and reconvergence points) and predicated execution to serialize these diverging paths. You will learn the tradeoffs of predication (avoiding branch penalties at the cost of wasting execution units on dummy work) and evaluate the tradeoffs of **Dynamic Warp Formation** (regrouping active threads to regain ALU utilization at the cost of register access efficiency and crossbar complexity). 

You will also cover GPU register file properties (such as high read-once rates and long dead times due to warp-interleaving), leading to optimizations like **Register Virtualization** and **Unified Structures** (combining register files and shared memory to maximize capacity utilization, albeit at the cost of complicating memory banking logic). Finally, you will explore **Data Transfer Optimizations**—weighing **pinned memory** (eliminating OS paging) against **zero-copy memory** (bypassing explicit copies but forcing slow PCIe reads)—and newer architectural features like **Independent Thread Scheduling** (which simplifies fine-grained locks and prevents deadlocks, though divergence penalties remain).

### 3. Virtual Memory & Performance Modeling (Modules 7-8)
Applying CPU concepts directly to GPUs often fails due to the scale of multithreading. You will explore the unique challenges of **GPU Virtual Memory**, where a single uncoalesced memory access could trigger 32 simultaneous TLB misses per warp. You will examine the tradeoffs of **Unified Virtual Address (UVA)** spaces—weighing programming simplicity against the severe PCIe latency overhead of on-demand page faulting. To mitigate this, you will explore prefetching strategies like **Tree-Based Neighborhood Prefetching**, which dynamically scales fetch sizes to balance spatial locality against unnecessary fetches, and the impact of allocating **Large Pages** (which reduce TLB pressure but introduce severe internal fragmentation).

You will also learn how to diagnose bottlenecks using the **Roofline Model**—a visual framework that plots Performance (GFLOPs) against Arithmetic Intensity (FLOPs/Byte). This tool instantly reveals whether a kernel is Compute-Bound (requiring instruction optimization) or Memory-Bound (requiring caching/coalescing optimization). Additionally, the course contrasts CPU schedulers (latency-focused) with GPU **Warp Schedulers** (throughput-focused). You will highlight the tradeoff between "fair" policies like Round-Robin (which can cause cache thrashing if the working set exceeds cache size) and "unfair" policies like Greedy-Then-Oldest (GTO) that preserve cache locality, as well as **Cache-Conscious Wavefront Scheduling** (limiting active warps to prevent thrashing at the cost of parallelism). Finally, the module distinguishes between analytical modeling (using warp depth as a "shock absorber" for memory latency) and cycle-level simulations, emphasizing the tradeoff between **execution-driven** (accurate on dynamic events like locks) and **trace-driven** (faster and reproducible) simulation methods.

### 4. The Compiler Pipeline and Data Flow (Modules 10-11)
Writing code for a machine that rapidly evolves across hardware generations requires a unique compilation strategy. You will explore the dual-compilation pipeline, distinguishing between the virtual instruction set (**PTX**, assuming infinite registers) and the physical machine code (**SASS**, with physical register allocation). You will learn the tradeoff of using **Fat Binaries**, which significantly inflate executable size to provide seamless portability and forward compatibility across GPU generations.

The course delves into compiler optimization techniques, teaching you how compilers use Intermediate Representations (IR), **Static Single-Assignment (SSA)** forms with Phi (Φ) functions, and Control Flow Graphs (CFGs) to analyze code. You will understand how static analysis tools use Gen and Kill sets for **Reaching Definitions** (moving forward) and track the lifespan of variables via **Live-Variable Analysis** (moving backward) to perform aggressive register allocation, weighing the tradeoff of freeing registers by **spilling** to memory versus the latency it introduces. The section also covers **Global Code Optimizations** (e.g., loop unrolling, function inlining, code motion) and their tradeoffs, such as how unrolling and inlining reduce overhead but lead to I-cache bloat. Finally, you will explore the challenges of static **Divergence Analysis** in identifying thread-dependent variables, highlighting how conservative static analysis may falsely penalize uniform branches to ensure safety.

### 5. Scaling Out: Multi-GPU and Datacenter Architecture (Module 9)
As single monolithic chips reach their manufacturing limits (due to low yield and high costs), architecture must scale outward using chiplets and multi-board setups. The course covers the hardware and software mechanisms used to connect multiple GPUs into cohesive supercomputers.

You will explore interconnect technologies like **NVLink** and **GPUDirect RDMA**, which allow GPUs to bypass the host CPU and communicate directly across PCI boundaries and network interfaces for zero-copy transfers (though RDMA introduces network hardware and security complexities). You will also build an intuition for **Non-Uniform Memory Access (NUMA)**, learning the tradeoffs of first-touch allocation (fast initial setup but expensive remote accesses) versus migrating memory pages to minimize the latency of "far" memory accesses. Finally, the module covers multi-tenant concurrency techniques, comparing the static, strict hardware isolation and guaranteed QoS of **MIG (Multi-Instance GPU)** against the dynamic resource sharing and higher overall throughput of **MPS (Multi-Process Service)** (which sacrifices strict predictability), alongside **Streams** for overlapping execution and transfers.

### 6. The Engine of Machine Learning (Module 12)
The final module connects the fundamental principles of GPU architecture to the specific demands of Deep Learning. 

You will examine the transition from general-purpose SIMD instructions to dedicated machine learning hardware, such as **Tensor Cores** and **Systolic Arrays** (weighing the tradeoff of large arrays wasting cycles filling/draining versus small arrays maximizing flexibility). These units execute entire matrix multiplications (GEMM) in a single hardware instruction, capitalizing on the high Arithmetic Intensity of ML workloads. You will learn how Asynchronous Copy Instructions and the Tensor Memory Accelerator (TMA) mitigate severe data movement bottlenecks. Finally, the course covers the profound impact of **Quantization** and **Structured Sparsity**—demonstrating how intentionally reducing floating-point precision (from FP32 down to FP16 or FP8) using non-uniform quantization (clustering bins near zero to preserve weight nuances), or enforcing rigid sparse patterns (e.g., 2:4 sparsity to simplify decompression hardware), drastically reduces memory bandwidth bottlenecks. This effectively doubles computational throughput for AI workloads while carefully managing the tradeoff with representational accuracy.
