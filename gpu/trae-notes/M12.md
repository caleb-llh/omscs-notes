## Lesson 1: GPU and ML

### Learning Objectives
* Explain the basic operations involved in machine learning workloads.
* Describe the benefits of utilizing GPUs for ML workloads.

### Why are GPUs Ideal for ML?
GPUs excel at ML acceleration due to several architectural advantages aligned with the needs of ML workloads:
* **High Data Parallelism:** ML workloads require massive amounts of floating-point operations. GPUs contain numerous floating-point arithmetic logic units (ALUs) specifically designed to handle parallel data processing.
* **High Memory Bandwidth:** GPU chips and memories are directly connected, enabling the integration of high-bandwidth memory (HBM) technologies.
* **Flexible Data Formats:** GPUs natively support diverse numerical formats optimized for ML, such as tensor formats, bfloat16, and low-precision integers (INT8/INT4).
* **Alignment with Statistical Computing:** ML relies on statistical computing, which perfectly matches the GPU's execution model. For instance, GPUs utilize a weak memory consistency model and do not guarantee precise exceptions—features that would require extra hardware overhead but are unnecessary for statistical ML workloads.

> **Intuition:** Think of a CPU as a few highly intelligent professors who can solve complex problems sequentially, while a GPU is an army of thousands of elementary school students who can perform simple arithmetic simultaneously. ML workloads look exactly like the latter—massive amounts of simple additions and multiplications.

### DNN Operation Categories
Deep Neural Network (DNN) operations are highly data-parallel and generally fall into three major categories:
1. **Element-wise Operations:** E.g., activation functions.
2. **Reduction Operations:** E.g., pooling layers (Max Pooling).
3. **Dot-product Operations:** E.g., General Matrix Multiplication (GEMM) and convolutions.

> **Example:** In a typical image recognition task (like ResNet), Convolutions (Dot-product) handle feature extraction, ReLU handles Element-wise operations, and Max Pooling handles Reduction.

### Background of GEMM
[![GEMM](https://lowyx.com/assets/posts/gatech/gpu/m12l1_gemm.png)](https://lowyx.com/assets/posts/gatech/gpu/m12l1_gemm.png)

GEMM (General Matrix Multiplication) is foundational for fully connected and convolutional layers. It is mathematically represented as:
**$C = \alpha AB + \beta C$**
*(Where $A$ is $M \times K$, $B$ is $K \times N$, and $C$ is $M \times N$. Constants $\alpha$ and $\beta$ can scale or nullify terms; e.g., setting $\alpha=1$ and $\beta=0$ yields $C = A \times B$.)*

> **Mental Model:** Every time you see a Neural Network layer with $M$ inputs and $N$ outputs, there's a weight matrix connecting them. Passing $K$ samples (a batch) through this layer is essentially a single GEMM operation.

**Arithmetic Intensity in GEMM:**
* Computing $A \times B$ requires $M \times N \times K$ Fused Multiply-Adds (FMA). Since one FMA equals two Floating-Point Operations (FLOPs), the total is **$2 \times M \times N \times K$ FLOPs**.
* Assuming FP16 inputs (2 bytes per element) and an FP32 accumulator, the memory bandwidth required to fetch the data is **$2 \times (M \times K + N \times K + M \times N)$ bytes**.
* **Arithmetic Intensity** = (Total FLOPs) / (Total Memory Bytes). Knowing the matrix dimensions allows you to compute this metric to estimate whether a given GPU's memory bandwidth can support the required intensity (assuming a first-order approximation where all inputs come directly from main memory, unoptimized by caches).

> **Tradeoff:** High Arithmetic Intensity is desirable because it means the GPU spends more time calculating than waiting for memory. If intensity is too low, the workload becomes "memory-bound," and those ultra-fast computation units sit idle.

### SIMD vs. Tensor Cores
[![Tensor Core](https://lowyx.com/assets/posts/gatech/gpu/m12l1_tensor.png)](https://lowyx.com/assets/posts/gatech/gpu/m12l1_tensor.png)

* **SIMD/SIMT Limitations:** Performing a $4 \times 4$ matrix multiplication conventionally using SIMD/SIMT requires 16 SIMD operations. It necessitates multiple threads and iterative loops. Because thread registers are private, accumulating the sum requires complex memory sharing and synchronization overhead.
* **Tensor Cores:** GPUs introduced dedicated matrix accelerators (Tensor Cores). Instead of sequential SIMD instructions, a single Tensor Core instruction (e.g., `HMMA.1688.F16`) can compute a $4 \times 4$ matrix multiplication with FP16 precision directly in hardware.

> **Background Context:** SIMT (Single Instruction, Multiple Threads) was revolutionary for graphics and general computing, but as Deep Learning matured, hardware architects realized that a $4 \times 4$ matrix multiply is so ubiquitous it deserved its own dedicated hardware instruction.

[![SIMD Matrix](https://lowyx.com/assets/posts/gatech/gpu/m12l1_simd_matrix.png)](https://lowyx.com/assets/posts/gatech/gpu/m12l1_simd_matrix.png)

### Tensor Cores Deep Dive
Tensor Cores natively perform massive matrix multiply-and-accumulate calculations. Hundreds of Tensor Cores operate concurrently in a modern NVIDIA GPU, exponentially increasing throughput and efficiency.
* **A100 Example:** A single A100 Tensor Core can execute 256 FP16 FMA operations per clock cycle. Performance is further boosted by supporting lower precisions (INT8, INT4, binary 1-bit predictions) and sparsity.

### Matrix Multiplications with Systolic Arrays
[![Systolic Array 1](https://lowyx.com/assets/posts/gatech/gpu/m12l1_matrix1.png)](https://lowyx.com/assets/posts/gatech/gpu/m12l1_matrix1.png)
[![Systolic Array 2](https://lowyx.com/assets/posts/gatech/gpu/m12l1_matrix2.png)](https://lowyx.com/assets/posts/gatech/gpu/m12l1_matrix2.png)

Matrix multiplications are traditionally hardware-accelerated via **Systolic Arrays**—a network of processing elements (blue boxes) where data flows rhythmically.
* **Data Flow:** Matrix $A$ elements flow row-wise, while matrix $B$ elements flow column-wise across the array.
* **Cycle-by-Cycle Execution:**
  * *Cycle 1:* $a_{11}$ and $b_{11}$ enter the top-left element, which computes $a_{11} \times b_{11}$ and stores the partial sum.
  * *Cycle 2:* $a_{11}$ passes to the next element horizontally, and $b_{11}$ passes vertically. Simultaneously, new elements ($a_{12}$ and $b_{21}$) enter the top-left element, accumulating their product into the existing partial sum.
  * *Cycle 4:* The array is fully populated and computing concurrently.
  * *Completion:* It takes about 7 cycles to completely fill and drain a $4 \times 4$ array to produce the final matrix $C$.

> **Mental Model:** Imagine a bucket brigade where instead of passing buckets of water, workers pass numbers. Each worker multiplies the number they receive from the left with the number from the top, adds it to their running total, and then passes the original numbers to their right and bottom neighbors.

### Transformer Engine
Introduced in NVIDIA's Hopper (GH) architecture, the Transformer Engine accelerates transformer network layers:
* **Dynamic Range Scaling:** Dynamically scales tensor data to fully utilize the representational range of lower-precision formats like FP8.
* **Efficient Data Movement:** Feeding Tensor Cores fast enough is a major bottleneck. The Transformer Engine utilizes **Tensor Memory Accelerator (TMA)** to asynchronously generate addresses using a copy descriptor and bulk-copy data, keeping the compute units fully utilized.

> **Intuition:** The Transformer Engine acts as an automatic transmission for precision. If a layer doesn't need high precision, it dynamically downshifts to FP8 to save bandwidth and boost speed, without requiring the programmer to manually rewrite the model.

## Lesson 2: Floating Point Formats

### Learning Objectives
* Describe IEEE floating-point formats.
* Explain the benefits of quantization in ML.

### FP16 vs. FP32
[![ML FP Formats](https://lowyx.com/assets/posts/gatech/gpu/m12l2_mlfp.png)](https://lowyx.com/assets/posts/gatech/gpu/m12l2_mlfp.png)

Traditional scientific computing relies on high precision (FP32 or FP64). ML workloads, however, are resilient to lower precisions.
By halving the precision from FP32 to FP16, the data size is halved. If an algorithm uses FP8 instead of FP16, the memory bandwidth requirement drops by half again, effectively **doubling the arithmetic intensity** without changing the number of FLOPs.

> **Tradeoff:** Using lower precision formats like FP16 or FP8 reduces memory bottlenecks and increases speed, but risks losing representational accuracy, which can sometimes degrade the model's predictive performance if not carefully managed.

### Benefits of Quantization
Quantization (reducing the precision of weights/activations) offers three major benefits:
1. **Reduced Storage Size:** Less data movement across the memory hierarchy.
2. **Increased Arithmetic Intensity:** Allows compute units to operate without memory starvation.
3. **Increased Throughput:** Newer ML accelerators physically compute more operations per cycle at lower precisions (e.g., FP8 throughput can be 2x that of FP16).

### Floating Point Basics
[![Floating Basics](https://lowyx.com/assets/posts/gatech/gpu/m12l2_floating_basics.png)](https://lowyx.com/assets/posts/gatech/gpu/m12l2_floating_basics.png)

Scientific notation (e.g., $1.2 \times 10^{-3}$) consists of a fraction ($1.2$) and an exponent ($-3$). Binary floating-point formats operate similarly but in base-2, consisting of:
* **Sign Bit (1 bit):** Indicates positive or negative.
* **Exponent Bits:** Determines the range of representable values.
* **Fraction (Mantissa) Bits:** Determines the precision.

> **Common Confusion:** It is easy to assume that floating-point numbers are evenly spaced on the number line. In reality, they are dense around zero and become increasingly sparse as the numbers get larger.

[![Different Formats](https://lowyx.com/assets/posts/gatech/gpu/m12l2_floating_basics_diff.png)](https://lowyx.com/assets/posts/gatech/gpu/m12l2_floating_basics_diff.png)

By adjusting the bit allocation, different formats are created (FP32, FP16, FP8, or even odd formats like 19-bit). More exponent bits cover a wider range, while more fraction bits yield higher precision.

### IEEE 754 Standards and Nuances
[![Floating Details](https://lowyx.com/assets/posts/gatech/gpu/m12l2_floating_basics_diff_details.png)](https://lowyx.com/assets/posts/gatech/gpu/m12l2_floating_basics_diff_details.png)
[![Floating Representation](https://lowyx.com/assets/posts/gatech/gpu/m12l2_floating_rep.png)](https://lowyx.com/assets/posts/gatech/gpu/m12l2_floating_rep.png)

* **Exponent Bias (Offset):** Exponents can be negative (for numbers $<1$) or positive (for numbers $>1$). IEEE 754 uses an offset (bias) to handle signs without a two's complement representation.
* **Denormalized (Subnormal) Values:** Used to represent values extremely close to zero, filling the gap between zero and the smallest normal floating-point number.
* **Resolution Distribution:** Floating-point numbers have fine-grained resolution near zero and lose precision as they approach the overflow limits. IEEE 754 also dictates special values (infinity, NaN) and rounding modes.

> **Background Context:** IEEE 754 was established in 1985 to standardize floating-point arithmetic across different computer manufacturers. Before this, porting numerical software between different machines was a nightmare because each handled rounding and edge cases differently.

### Quantization Challenges and Solutions
[![Quantization](https://lowyx.com/assets/posts/gatech/gpu/m12l2_quant.png)](https://lowyx.com/assets/posts/gatech/gpu/m12l2_quant.png)

A common ML technique is computing inputs at low precision while accumulating results in higher precision.
Because floating-point numbers naturally cluster around zero, uniform quantization wastes representational power. **Non-uniform quantization** techniques (like shifted and squeezed 8-bit formats) apply value transformations to allocate more representational states near zero, which is crucial for preserving the integrity of ML workloads.

> **Hypothetical:** If you quantized a neural network using uniform bins, most of your representational bins near the edges would sit completely empty, while the single bin near zero would be overcrowded, completely destroying the nuance of the model's weights.

## Lesson 3: Designing Tensor Cores

### Learning Objectives
* Describe architectural design methods for ML accelerator components on GPUs.
* Explain the main design criteria and trade-offs.

### Designing ML Accelerator Units
When adding dedicated hardware accelerators to a GPU, architects must evaluate:
1. **Identify Target Operations:** Profile workloads or analyze algorithms to find frequently executed operations.
2. **Evaluate Performance Gains:** Determine the benefit of a dedicated hardware unit versus optimizing existing SIMD/software instructions.
3. **Hardware Interface Design:** Define new ISAs, programming models, and data-feeding mechanisms.
4. **Integration Trade-offs:** Decide whether to merge multiple accelerator features into one component (improves usability but adds area and timing overhead).

> **Tradeoff:** Every square millimeter of silicon dedicated to a specialized accelerator (like a Tensor Core) is silicon taken away from general-purpose programmable cores. This means specializing makes the GPU faster for ML but potentially less capable for traditional graphics or generalized compute.

### Matrix Multiplication Accumulator (MMA) Design
[![MMA Design](https://lowyx.com/assets/posts/gatech/gpu/m12l3_matrix.png)](https://lowyx.com/assets/posts/gatech/gpu/m12l3_matrix.png)

* **Size Trade-offs:** Should the GPU use many small matrix units or fewer large ones (like a large systolic array)? Larger units risk wasting cycles on filling and draining. Smaller units minimize this overhead. (e.g., NVIDIA started with $4 \times 4$, while Intel's AMX supports $16 \times 16$).
* **Area vs. Programmability:** Dedicating more silicon area to MMA units takes resources away from general-purpose GPU components.
* **Implementation Options:**
  * *Parallel Units:* Instantiate multiple units handling different rows/columns simultaneously.
  * *Pipelining:* Share hardware by pipelining the load, compute, and store phases across cycles to maximize throughput without excessively duplicating hardware.

> **Example:** Google's TPU took the approach of a massive systolic array (e.g., $256 \times 256$), which is incredibly efficient for massive models but incurs high latency to fill and drain. NVIDIA opted for many smaller units (like $4 \times 4$ or $16 \times 16$) to maintain flexibility across diverse workloads.

### Data Storage and Movement
[![Data Storage](https://lowyx.com/assets/posts/gatech/gpu/m12l3_storage.png)](https://lowyx.com/assets/posts/gatech/gpu/m12l3_storage.png)

Tensor operations demand massive data influx.
* **Registers vs. Shared Memory:** A $4 \times 4 \times 4$ matrix operation requires significant register space ($3 \times 16$). Since GPU thread registers are private, coordinating data sharing is complex.
* **Asynchronous Copies:** To bypass register bottlenecks, NVIDIA introduced **Asynchronous Copy Instructions** and **Asynchronous Barriers**. These allow data to stream directly from Global Memory into Shared Memory (optionally bypassing L1 cache), positioning data perfectly for the Tensor Core.

> **Common Confusion:** Beginners often think computation speed is the bottleneck in ML. In reality, modern GPUs calculate so fast that getting the data from memory into the calculation units (the "Data Movement") is usually the primary bottleneck.

### Supporting Sparse Operations
[![Sparse Ops](https://lowyx.com/assets/posts/gatech/gpu/m12l3_sparse.png)](https://lowyx.com/assets/posts/gatech/gpu/m12l3_sparse.png)
[![Sparse Hardware](https://lowyx.com/assets/posts/gatech/gpu/m12l3_sparse2.png)](https://lowyx.com/assets/posts/gatech/gpu/m12l3_sparse2.png)

With algorithmic pruning, matrices become highly sparse (mostly zeros), making SpMV (Sparse Matrix-Vector multiplication) a critical research topic.
* **Software Sparsity:** Uses compressed formats (like Compressed Sparse Row/Column), storing only non-zero values alongside their row/column indices. However, storing variable indices incurs storage overhead.
* **Hardware Structured Sparsity:** Modern GPUs accelerate **Structured Sparsity** (e.g., assuming a strict 50% sparsity pattern).
  * By enforcing a rigid pattern (e.g., 2 non-zeros out of 4 elements), the hardware only requires a minimal index (e.g., 1-bit per block to indicate if a value comes from the left or right column).
  * This drastically simplifies the decompression hardware, cuts storage requirements in half, and improves overall compute throughput.

> **Intuition:** Structured sparsity is like having a strict diet rule: "You can eat any 2 meals out of 4 every day." Because the rule is strict, the hardware doesn't need complex tracking systems to know what's going on—it can just rely on the 2-out-of-4 pattern to compress and decompress data effortlessly.
