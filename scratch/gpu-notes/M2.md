## Lesson 1: Parallel Programming Patterns

**Objective:** Provide an overview of different parallel programming paradigms.

### Creating a Parallel Application
To create a parallel application, a program's tasks are broken down. The workload is divided, data structures are adjusted for parallel execution, and the work is distributed across multiple processors.

[![Parallel Application](https://lowyx.com/assets/posts/gatech/gpu/m2l1_parallelapp.png)](https://lowyx.com/assets/posts/gatech/gpu/m2l1_parallelapp.png)

### Steps to Write Parallel Programs
1. **Discover Concurrency:** Identify opportunities for parallelism in your task or problem. This is the starting point for any parallel programming endeavor.
2. **Structure the Algorithm:** Organize your code to effectively exploit the identified concurrency.
3. **Implementation:** Choose a suitable programming environment, language, and toolset to write the code.
4. **Execution and Optimization:** Run the code on a parallel system and fine-tune it to achieve optimal performance.

### Five Popular Parallel Programming Patterns

1. **Master/Worker Pattern:** 
   A single master process or thread manages a pool of worker threads and a task queue. Workers concurrently execute tasks by dequeuing them from the shared queue. This Single Program, Multiple Data (SPMD) approach is ideal for tasks that can be broken down into smaller, independent pieces.
   [![Master/Worker Pattern](https://lowyx.com/assets/posts/gatech/gpu/m2l1_master_worker_pattern.png)](https://lowyx.com/assets/posts/gatech/gpu/m2l1_master_worker_pattern.png)

2. **Loop Parallelism Pattern:**
   Loops are excellent candidates for parallelism because they often involve repetitive, independent iterations. Unlike the master/worker pattern, the tasks inside the loops are typically identical. Each iteration can be executed in parallel.
   ```cpp
   for (i = 0; i < 16; i++) {
       c[i] = A[i] + B[i];
   }
   ```

3. **SPMD Pattern (Single Program, Multiple Data):**
   All processing elements execute the same program in parallel, but each operates on its own unique set of data. This is a very popular paradigm, especially in GPU programming.

4. **Fork/Join Pattern:**
   This pattern combines serial and parallel processing. A parent task creates (forks) new tasks, executes them in parallel, and waits for their completion (joins) before moving to the next serial task. It is frequently used in programs with a single entry point.
   [![Fork/Join Pattern](https://lowyx.com/assets/posts/gatech/gpu/m2l1_forkjoin_pattern.png)](https://lowyx.com/assets/posts/gatech/gpu/m2l1_forkjoin_pattern.png)

5. **Pipeline Pattern:**
   Resembling a CPU pipeline, different parallel processors work on successive stages of a task. It is ideal for processing continuous data streams, such as signal processing, graphics pipelines, or compression workflows (e.g., decompression -> processing -> compression).
   [![Pipeline Pattern](https://lowyx.com/assets/posts/gatech/gpu/m2l1_pipeline_pattern.png)](https://lowyx.com/assets/posts/gatech/gpu/m2l1_pipeline_pattern.png)

## Lessons 2 & 3: OpenMP and Shared Memory Programming

**Objectives:**
* Understand shared memory programming concepts.
* Explore the primary components, scheduling, and synchronization mechanisms of OpenMP.

### Memory Models: Shared vs. Distributed
* **Shared Memory:** All processors access the same memory space. If Processor 1 updates a value, Processor 2 can observe the update simply by reading from the shared memory.
  [![Shared Memory](https://lowyx.com/assets/posts/gatech/gpu/m2l2_shared_mem.png)](https://lowyx.com/assets/posts/gatech/gpu/m2l2_shared_mem.png)
* **Distributed Memory:** Each processor has its own private memory space. To access data in another processor's memory, they must explicitly send and receive messages over a network.
  [![Distributed Memory](https://lowyx.com/assets/posts/gatech/gpu/m2l2_shared_mem_distributed.png)](https://lowyx.com/assets/posts/gatech/gpu/m2l2_shared_mem_distributed.png)

### Introduction to Threads
A **thread** is an entity that executes a sequence of instructions. It is a software concept; a thread has its own register state and stack memory. One CPU core can run one or multiple threads. Note that the concept of a thread differs slightly between CPUs and GPUs.

### Overview of OpenMP
OpenMP is an open standard for parallel programming on shared memory systems. It consists of compiler directives, library routines, and environment variables.
Key tasks in parallel programming with OpenMP include:
* Parallelization
* Specifying thread counts
* Scheduling
* Data sharing policies
* Thread synchronization

### Data Decomposition & Vector Sum Example
To process an array in parallel, we use **data decomposition**. For instance, a 10-element array can be split in half, with each half assigned to a different core/thread to compute a partial sum.
[![Data Decomposition](https://lowyx.com/assets/posts/gatech/gpu/m2l2_data_decomposition.png)](https://lowyx.com/assets/posts/gatech/gpu/m2l2_data_decomposition.png)
[![Data Decomposition 2](https://lowyx.com/assets/posts/gatech/gpu/m2l2_data_decomposition2.png)](https://lowyx.com/assets/posts/gatech/gpu/m2l2_data_decomposition2.png)

**Serial Vector Sum:**
```cpp
int main() {
  const int size = 10;
  int data[size];
  int sum = 0;
  for (int i = 0; i < size; ++i) {
     sum += data[i];
  }
  std::cout << "Sum of array elements: " << sum << std::endl;
  return 0;
}
```

**Parallel Vector Sum with OpenMP:**
Using low-level APIs (like pthreads) requires manual thread creation, joining, and mutex handling. OpenMP simplifies this drastically using the `#pragma omp parallel for reduction(+:sum)` directive:
```cpp
#include <iostream>
#include <omp.h>

int main() {
  const int size = 1000;
  int data[size];
  int sum = 0;
  
  #pragma omp parallel for reduction(+:sum)
  for (int i = 0; i < size; ++i) {
     sum += data[i];
  }
  
  std::cout << "Sum of array elements: " << sum << std::endl;
  return 0;
}
```
* **Directives:** `#pragma omp directive [clause...]` instruct the compiler to insert parallel runtime library calls.
* **Reduction Clause (`reduction(+:sum)`):** Automatically handles the merging of partial sums computed by different threads, preventing data races.

### Managing Thread Counts
By default, OpenMP uses the number of available hardware cores. You can control this via:
* Environment variable: `export OMP_NUM_THREADS=4`
* In code: `omp_set_num_threads(4);`

### Scheduling Strategies
When distributing loop iterations among threads, uneven progress can occur (e.g., if one core handles more threads than another). OpenMP offers different scheduling options to address this:
1. **Static Scheduling:** Evenly divides the total work into fixed chunks (e.g., 200k elements per thread). Best when all iterations take the same amount of time.
2. **Dynamic Scheduling (Small Chunk):** Threads are given a small chunk (e.g., 1 element) and request more work when finished. This ensures optimal load balancing but has high overhead.
3. **Dynamic Scheduling (Large Chunk):** Threads are given larger chunks (e.g., 1,000 elements) at a time to reduce the overhead of requesting more work.
4. **Guided Scheduling:** The chunk size starts large and progressively decreases over time, adapting to runtime conditions and balancing overhead with load distribution.

### Data Sharing and Thread Synchronization
Data sharing policies determine whether variables are **private** (each thread gets its own copy, like partial sums) or **shared** (all threads access the same memory, like the total sum).

Synchronization ensures correct execution when multiple threads access shared resources.
1. **Mutex (Mutual Exclusion):** Ensures only one thread accesses a critical section at a time by acquiring and releasing a lock.
2. **Critical Section (`#pragma omp critical`):** Prevents data races by allowing only one thread to execute the guarded block of code at a time.
   ```cpp
   #pragma omp parallel num_threads(4) 
   {
       #pragma omp critical 
       {
           // Only one thread enters here at a time
       }
   }
   ```
   [![Critical Section](https://lowyx.com/assets/posts/gatech/gpu/m2l3_critical.png)](https://lowyx.com/assets/posts/gatech/gpu/m2l3_critical.png)
3. **Atomic Operations (`#pragma omp atomic`):** Guarantees that a specific operation (like `counter++`) completes entirely in one uninterruptible step, leveraging hardware support when possible for better performance than a full critical section.
4. **Barrier (`#pragma omp barrier`):** A synchronization point where all threads must wait until every thread has reached the barrier before any can proceed. Useful for managing task dependencies.
   [![Barrier](https://lowyx.com/assets/posts/gatech/gpu/m2l3_barrier.png)](https://lowyx.com/assets/posts/gatech/gpu/m2l3_barrier.png)

### Parallel Sections
When parallel tasks are not loop-based, you can use the `sections` directive.
```cpp
#pragma omp parallel sections 
{
  #pragma omp section
  { /* work-1 */ }
  #pragma omp section
  { /* work-2 */ }
}
```
* **Ordered (`#pragma omp ordered`):** Ensures that threads execute a block of code in the sequential order of loop iterations, even if processed in parallel.
  [![Ordered](https://lowyx.com/assets/posts/gatech/gpu/m2l3_ordered.png)](https://lowyx.com/assets/posts/gatech/gpu/m2l3_ordered.png)
* **Single (`#pragma omp single`):** Specifies that a block of code should be executed by *only one* thread (whichever reaches it first), useful for initializations or single I/O operations.

## Lesson 4: Distributed Memory Programming with MPI

**Objectives:**
* Describe the fundamental concepts of distributed memory parallel programming.
* Gain understanding of the Message Passing Interface (MPI).

### Why Study Both OpenMP and MPI?
GPU programming (like CUDA) often combines paradigms from both shared memory (OpenMP) and distributed memory (MPI). Some memory regions in a GPU are shared among all cores, while others are isolated and require explicit communication between blocks.

### MPI Programming Basics
MPI is a powerful communication model for parallel computing across distributed systems. Since each process has its own isolated memory, they must explicitly send and receive data.
[![MPI Programming](https://lowyx.com/assets/posts/gatech/gpu/m2l4_mpi_programming.png)](https://lowyx.com/assets/posts/gatech/gpu/m2l4_mpi_programming.png)
* **`MPI_Send()` & `MPI_Recv()`:** Used for point-to-point communication between two specific processes.
* **`MPI_Bcast()` (Broadcasting):** A collective communication function that sends data from one process to all other processes globally.
  [![Broadcasting](https://lowyx.com/assets/posts/gatech/gpu/m2l4_broadcasting.png)](https://lowyx.com/assets/posts/gatech/gpu/m2l4_broadcasting.png)

### Example: Stencil Operations
Stencil operations are common in High-Performance Computing (HPC). They involve computing a value based on neighboring data (e.g., averaging the top, bottom, left, and right neighbors).
[![Stencil](https://lowyx.com/assets/posts/gatech/gpu/m2l4_stencil.png)](https://lowyx.com/assets/posts/gatech/gpu/m2l4_stencil.png)

**The Challenge:**
If the dataset is split across four distributed processes, a process can easily compute the stencil for its internal data. However, computing the values at the edges requires data located in another process's memory.
[![Stencil 2](https://lowyx.com/assets/posts/gatech/gpu/m2l4_stencil2.png)](https://lowyx.com/assets/posts/gatech/gpu/m2l4_stencil2.png)

**The Solution:**
To perform these boundary computations, processes must explicitly communicate the boundary information (often called a "halo") via messages before performing the computation.
[![Stencil 3](https://lowyx.com/assets/posts/gatech/gpu/m2l4_stencil3.png)](https://lowyx.com/assets/posts/gatech/gpu/m2l4_stencil3.png)
