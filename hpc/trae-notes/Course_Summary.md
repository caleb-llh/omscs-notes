# High Performance Computing: Course Overview

## Introduction
For decades, algorithm design was dominated by the RAM (Random Access Machine) model—a mathematically beautiful abstraction that assumes fetching any piece of data takes exactly $O(1)$ time, and a single processor executes instructions sequentially. However, the physical realities of modern hardware have shattered this illusion. The breakdown of Dennard Scaling (the "Power Wall") forced the industry into multicore parallelism, while the growing disparity between CPU speeds and memory latency (the "Memory Wall") made data movement the true bottleneck of computing.

This course explores **High Performance Computing (HPC)** by explicitly stepping beyond the RAM model. It provides the theoretical and practical foundations to design algorithms that scale across thousands of cores, minimize expensive data movement, and exploit the physical architecture of supercomputers. By the end of this course, you will understand how to fundamentally rethink classical algorithms to survive and thrive in parallel, cache-bound, and distributed-memory environments.

## Core Themes and Conceptual Framework

### 1. The Physics of Computing and the Work-Span Model
Before writing parallel code, we must understand how to measure it. The course begins by replacing standard time complexity with the **Work-Span Model**. If an algorithm is a dependency graph (DAG), "Work" ($W$) is the total number of operations, and "Span" ($D$) is the longest critical path of sequential dependencies. 

You will learn to evaluate the maximum available parallelism of any algorithm ($\frac{W}{D}$) and utilize concurrency primitives (`spawn` and `sync`) to express nested parallelism. Using Brent's Theorem, you will discover that a good parallel algorithm is "short and wide," maintaining optimal work while achieving a polylogarithmic span through the divide-and-conquer paradigm. You will navigate the **Granularity Tradeoff**, balancing the desire for maximum parallelism against the overhead of thread synchronization. You will also contrast **Strong Scaling** (fixed problem size, governed by Amdahl's Law) with **Weak Scaling** (fixed work per processor, governed by Gustafson's Law), and explore edge cases like **superlinear speedup** where aggregated cache sizes unexpectedly reduce memory latency. Furthermore, the course grounds these metrics in physical reality: you will explore the Dynamic Power Equation ($P \propto F^3$), demonstrating why running multiple cores at a lower speed consumes vastly less power than one core at full speed, linking algorithmic energy directly to total Work.

### 2. Parallel Algorithmic Primitives
Standard sequential algorithms (like traversing a linked list) fail in parallel environments because their span is strictly linear ($O(N)$). You will learn how to break these sequential dependencies using powerful HPC primitives:
* **Prefix Sums (Scans) & List Ranking:** Using techniques like "pointer jumping" to turn sequential $O(N)$ traversal into parallel $O(\log N)$ span, though often trading higher total work ($O(N \log N)$) for a shallower critical path. You will also learn work-optimal list ranking ($O(N)$ work) using randomized independent sets and list contraction.
* **Tree Computations:** Utilizing Euler tours for **Linearization**, converting rigid hierarchical trees into flat arrays in $O(1)$ time. This trades doubled memory usage (storing directed edges) for the ability to unleash highly-optimized SIMD array primitives (like parallel prefix-sums) to compute properties like node depth or subtree size.
* **Sorting Networks:** Shifting from data-dependent sorts (like Quicksort) to **Bitonic Sorting**—a data-oblivious sorting network that maps perfectly to SIMD/GPU hardware. While it does more total work ($O(N \log^2 N)$) than asymptotically optimal networks (like AKS), its fixed, predictable communication patterns eliminate branch penalties and achieve massive, practical parallelism.

### 3. Locality and the Cost of Data Movement
In HPC, computing a mathematical operation is practically free; moving the data from memory to the CPU is the true cost. You will learn to analyze algorithms using the **External Memory (I/O) Model**, optimizing for Block size ($B$ or $L$) and Cache size ($M$ or $Z$). You will learn that multi-way merging achieves optimal external sorting by treating fast memory as an **Entropy Funnel** (maximizing uncertainty reduction before data hits the narrow memory bus), and B-Trees provide IO-optimal searching.
* **The Roofline Model:** A visual framework that plots Algorithmic Intensity (FLOPs per byte, the "miles per gallon" of computation) against Peak Performance, instantly revealing whether an algorithm is compute-bound or memory-bound based on the hardware's Machine Balance.
* **Cache-Oblivious Algorithms:** You will explore elegant divide-and-conquer strategies that inherently minimize cache misses across *all* levels of the memory hierarchy simultaneously. You will navigate the tradeoff between **Resource-Aware** algorithms (brittle, machine-specific tuning like a manual transmission) and **Cache-Oblivious** algorithms (automatically adapting to any hierarchy like a continuously variable transmission, though occasionally carrying a higher constant-factor overhead). By leveraging the Ideal-Cache model, justified by the **LRU Competitiveness Lemma**, and fractal layouts (like van Emde Boas search trees), these algorithms hit the hardware's memory "sweet spot" without needing explicit parameters. Analysis often relies on the **Tall-Cache Assumption** ($Z \ge L^2$) to ensure non-interfering 2D block caching.

### 4. Distributed Memory and Communication
When problems exceed the RAM of a single machine, we must scale out to distributed clusters. Here, the shared-memory illusion vanishes, and processors must explicitly send messages to one another following the **SPMD (Single-Program, Multiple-Data)** paradigm.
* **Topologies & The Alpha-Beta Model:** You will learn how physical network wires (Torus, Hypercube, Fat-Tree) limit performance via fundamental tradeoffs between **Bisection Width** (bandwidth bounds) and **Diameter** (latency bounds). You will model communication costs using latency ($\alpha$) and inverse bandwidth ($\beta$), managing the tradeoff of message coalescing (delaying sends to pack large payloads, minimizing $\alpha$) versus immediate transmission. You will also explore the congestion that arises when elegant **Logical Topologies** (like Hypercubes) are mapped onto restrictive **Physical Topologies** (like 3D Torus).
* **MPI (Message Passing Interface):** You will transition from theory to practice, learning how to orchestrate point-to-point asynchronous messages (`MPI_Isend`) to overlap computation and hide network latency. You will utilize powerful **Collective Operations** (Broadcast, Reduce, Scatter, Gather) across thousands of isolated nodes, learning to compose these optimally. For example, you will contrast Tree topologies (which minimize latency) with Ring topologies (which minimize bandwidth), ultimately achieving bandwidth-optimal broadcasts via Scatter followed by Ring All-Gather.

### 5. Distributed Algorithmic Case Studies
To solidify distributed concepts, the course deep-dives into two foundational case studies:
* **Distributed Matrix Multiplication:** You will trace the evolution from simple 1D layouts to the highly scalable 2D **SUMMA** algorithm. You will explore the **Loomis-Whitney geometric bound**, which mathematically proves the absolute minimum communication required. You will see how **2.5D and 3D algorithms** explicitly trade memory capacity (static power) to redundantly replicate matrices, drastically reducing network bandwidth (dynamic power and time) in modern power-constrained exascale systems.
* **Distributed Sorting:** You will examine how Bitonic Merges perfectly map to hypercube and butterfly network topologies. You will navigate the tradeoff between the safe, data-oblivious predictability of Bitonic Sort and the raw speed of data-driven algorithms like **Sample Sort**. You will learn how the latter uses hierarchical statistical sampling to establish bucket boundaries, risking severe load imbalance if the initial sample is skewed, but achieving extreme performance otherwise.

### 6. Graph Analytics at Scale
Real-world data (social networks, web graphs) is highly irregular and sparse, making it the ultimate stress test for HPC.
* **Shared-Memory BFS:** You will evaluate the tradeoff between **Level-Synchronous** traversal (which guarantees shortest paths but suffers from stragglers at synchronization barriers) and **Asynchronous** traversal (which maximizes CPU utilization but does redundant work). You will learn how to replace highly-contended sequential queues with lock-free, parallel **Bag/Pennant data structures**, completely sacrificing spatial locality and FIFO ordering to unlock infinite parallel bandwidth and manage benign data races.
* **Distributed BFS via Linear Algebra:** To scale across clusters, you will learn to cast graph traversal as a sparse matrix-vector multiplication (**SpMV**) over a Boolean (or Tropical) semiring. This highlights the tradeoff between pointer-based structures (ideal for dynamic graphs) and sparse matrices (which maximize cache hits for static graphs). Masking operations stencil out previously visited vertices, preventing redundant work, while **2D block-cyclic partitioning** bounds frontier replication to processor rows and columns, solving the severe $\mathcal{O}(P)$ latency bottlenecks of 1D layouts.
* **Graph Partitioning:** Finally, you will explore the NP-complete problem of dividing a graph across a network, navigating the fundamental tension between perfectly load-balancing vertices and minimizing cross-partition edge cuts. You will study heuristics ranging from the **Kernighan-Lin** algorithm, to **Multi-level Coarsening** (acting as a low-pass filter to trade moderate memory for massive speedups), and the mathematically beautiful but compute-intensive **Spectral Partitioning** (using the eigenvectors of the Graph Laplacian).

### Conclusion
By abandoning the comfortable illusions of the RAM model, this course equips you with "hardware sympathy." You will emerge with the mathematical frameworks to prove communication lower bounds and the practical design patterns to build algorithms that genuinely scale on the world's largest supercomputers.
