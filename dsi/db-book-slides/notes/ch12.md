# Chapter 12: Physical Storage Systems

## 1. Storage Hierarchy

![Storage Hierarchy](../images/ch12_slides/slide_002.png)

*   **Primary Storage**: Cache and main memory.
*   **Volatile Storage**: Loses its contents when power to the device is removed.
*   **Non-Volatile Storage**: Contents persist even when power is removed.
*   **Secondary Storage**: Flash memory, magnetic disks.
*   **Tertiary Storage**: Magnetic tapes, optical disks.

### Access Times

*   **Cache**: 1–5 nanoseconds (cache-line-at-a-time).
*   **Main Memory**: 60–100 nanoseconds (cache-line-at-a-time).
*   **Flash Storage / Solid-State Disks**: 20–100 microseconds (page-at-a-time).
*   **Magnetic Disks**: 5–10 milliseconds (page-at-a-time).
*   **Optical Disks**: 100+ milliseconds.
*   **Magnetic Tapes**: 10–100 seconds or more.

---

## 2. Storage Interfaces

*   **SATA (Serial ATA)**: SATA 3 supports data transfer speeds of up to 6 gigabits/sec.
*   **SAS (Serial Attached SCSI)**: SAS Version 3 supports 12 gigabits/sec.
*   **NVMe (Non-Volatile Memory Express)**: Works with PCIe connectors to support lower latency and higher transfer rates (up to 24 gigabits/sec).
*   **Direct Connection**: Disks are usually connected directly to the computer system.
*   **SAN (Storage Area Networks)**: A large number of disks are connected by a high-speed network to a number of servers.
*   **NAS (Network Attached Storage)**: Networked storage provides a file system interface using a networked file system protocol, instead of providing a direct disk system interface.

## 3. Magnetic Hard Disks

![Magnetic Hard Disk Mechanism](../images/ch12_slides/slide_005.png)

### Disk Controller

The interface between the computer system and the disk drive hardware:
*   Accepts high-level commands to read or write a sector.
*   Initiates actions such as moving the disk arm to the right track and reading/writing the data.
*   Computes and attaches **checksums** to each sector to verify that data is read back correctly. If data is corrupted, the stored checksum won’t match the recomputed checksum.
*   Ensures successful writing by reading back the sector after writing it.
*   Performs remapping of bad sectors.

### Performance Measures

*   **Access Time**: The time it takes from when a read or write request is issued to when data transfer begins.
    *   **Seek Time**: Time to reposition the arm over the correct track (typically 4–10 milliseconds). Average seek time is 1/2 the worst-case seek time (or 1/3 if ignoring start/stop time and assuming uniform tracks).
    *   **Rotational Latency**: Time for the target sector to appear under the head (typically 4–11 milliseconds for 5400–15000 RPM). Average latency is 1/2 of the full rotation time.
    *   **Overall Latency**: Usually 5 to 20 milliseconds depending on the disk model.
*   **Data-Transfer Rate**: The rate at which data can be retrieved or stored. Max rate is 25 to 200 MB/sec (lower for inner tracks).
*   **Disk Block**: The logical unit for storage allocation and retrieval (typically 4 to 16 kilobytes).
    *   Smaller blocks: More transfers from disk.
    *   Larger blocks: More space wasted due to partially filled blocks.
*   **Access Patterns**:
    *   **Sequential Access**: Successive requests are for successive disk blocks. Seek is required only for the first block.
    *   **Random Access**: Successive requests are for blocks anywhere on the disk. Each access requires a seek, leading to low transfer rates.
*   **IOPS (I/O Operations Per Second)**: Number of random block reads a disk can support per second. Magnetic disks typically support 50 to 200 IOPS.

### Reliability

*   **MTTF (Mean Time To Failure)**: Average time a disk is expected to run continuously without any failure (typically 3 to 5 years). A new disk's "theoretical MTTF" is 500,000 to 1,200,000 hours.
*   **AFR (Annualized Failure Rate)**: Calculated as `((365 * 24) / MTTF) * 100%`. For example, an MTTF of 1,200,000 hours corresponds to an AFR of 0.73%.

## 4. Flash Storage

*   **NAND vs. NOR Flash**: NAND is widely used for storage and is cheaper than NOR flash.
*   **NAND Characteristics**:
    *   Requires **page-at-a-time** reads (page size: 512 bytes to 4 KB). Reading takes 20 to 100 microseconds.
    *   Not much difference between sequential and random read performance.
    *   Pages can only be written once and must be **erased** before rewrite.
*   **Solid State Disks (SSDs)**: Use standard block-oriented disk interfaces, but store data on multiple flash storage devices internally. SATA transfer rates up to 500 MB/sec; NVMe PCIe up to 3 GB/sec.

### Erase Blocks and Remapping

*   Erase happens in units of an **erase block** (typically 256 KB to 1 MB, or 128 to 256 pages) and takes 2 to 5 milliseconds.
*   **Flash Translation Layer (FTL)**: Tracks and remaps logical page addresses to physical page addresses to avoid waiting for erase operations.
*   **Wear Leveling**: Flash blocks wear out after many erases (e.g., 100,000 for SLC, 1,000 to 10,000 for TLC/QLC). Wear leveling safely distributes erases by storing infrequently updated ("cold") data in blocks that have already been heavily erased.

### SSD Performance Metrics

*   **IOPS**:
    *   Random 4 KB reads: ~10,000 IOPS. With parallel requests (Queue Depth 32), up to 100,000 IOPS on SATA, and 350,000 IOPS on NVMe.
    *   Random 4 KB writes: ~40,000 IOPS. Up to 100,000+ IOPS with parallel requests.
*   **Transfer Rate**: Sequential reads/writes reach ~400 MB/sec for SATA3 and 2–3 GB/sec for NVMe PCIe.
*   **Hybrid Disks**: Combine a small amount of flash cache with a larger magnetic disk.

## 5. Storage Class Memory

*   **3D-XPoint**: Memory technology pioneered by Intel (available as Intel Optane).
*   Allows lower latency than flash SSDs.
*   Provides a non-volatile memory interface that supports direct access to words at speeds comparable to main-memory speeds.

## 6. RAID (Redundant Arrays of Independent Disks)

RAID manages a large number of disks to provide a view of a single disk with high capacity, high speed (parallelism), and high reliability (redundancy).

### Reliability via Redundancy

*   **Redundancy**: Storing extra information that can be used to rebuild lost data.
*   **Mirroring (Shadowing)**: Duplicating every disk. Every write is carried out on both disks; reads can take place from either. Drastically increases the mean time to data loss.

### Performance via Parallelism

*   Goals:
    1.  Load balance multiple small accesses to increase throughput.
    2.  Parallelize large accesses to reduce response time.
    3.  Improve transfer rate by striping data across multiple disks.
*   **Block-Level Striping**: With *n* disks, block *i* of a file goes to disk `(i mod n) + 1`. This allows parallel reads/writes for sequence blocks.

### RAID Levels

![RAID Levels](../images/ch12_slides/slide_018.png)
![RAID Levels (Cont.)](../images/ch12_slides/slide_019.png)
![RAID Levels (Cont.)](../images/ch12_slides/slide_020.png)
![RAID Levels (Cont.)](../images/ch12_slides/slide_021.png)

*   **RAID 0 (Non-redundant striping)**: High-performance block striping; no data protection.
*   **RAID 1 (Mirrored disks)**: Mirrored disks with block striping. Offers the best write performance (popular for log files).
*   **RAID 2 & 3**: Memory-style ECC and bit-interleaved parity (rarely used in practice).
*   **RAID 4 (Block-interleaved parity)**: Uses a dedicated parity disk. For random writes, the parity disk gets a heavy write load and becomes a bottleneck.
*   **RAID 5 (Block-interleaved distributed parity)**: Partitions data and parity among all disks. Block writes occur in parallel if they map to different disks.
*   **RAID 6 (P + Q redundancy)**: Similar to RAID 5 but stores two error correction blocks to guard against multiple disk failures. Becoming more important as storage capacities increase.

### Choice of RAID Level

*   **RAID 0**: Used only when data safety is not important.
*   **RAID 1**: Preferred for applications with many random/small updates (best write performance, but highest storage cost).
*   **RAID 5**: Preferred for applications where writes are sequential and large, requiring large storage capacity.
*   **RAID 6**: Provides better data protection against two simultaneous disk failures (or a latent block failure combined with a disk failure).

### Hardware Issues

*   **Hardware vs. Software RAID**: Hardware RAID uses non-volatile RAM (NV-RAM) to record active writes. This prevents disk corruption if power fails during a write and allows efficient detection of corrupted blocks.
*   **Latent Sector Failures**: Data successfully written earlier gets damaged. Resolved using **Data Scrubbing** (continual scanning for latent failures and recovering from parity).
*   **Hot Swapping**: Replacement of a disk while the system is running.
*   **Spare Disks**: Kept online to immediately replace failed disks, reducing recovery time.

## 7. Optimization of Disk-Block Access

*   **Buffering**: Using an in-memory buffer to cache disk blocks.
*   **Read-Ahead**: Reading extra blocks from a track in anticipation that they will be requested soon.
*   **Disk-Arm-Scheduling Algorithms**: Re-ordering block requests to minimize disk arm movement (e.g., the **elevator algorithm**).

---

## 8. Magnetic Tapes

*   **Characteristics**: Hold large volumes of data (up to petabytes in tape jukeboxes) and provide high transfer rates (tens of MB/sec).
*   **Cost**: Tapes are very cheap, but tape drives are very expensive.
*   **Access**: Very slow access time, limited to sequential access.
*   **Use Cases**: Used mainly for backups, storing infrequently used information, and offline data transfer.
