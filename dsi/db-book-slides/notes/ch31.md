## 1. Information Retrieval Systems
- **Data Model:** Simpler than database systems. Information is organized as a collection of documents.
- **Schema:** Documents are unstructured; there is no schema.
- **Functionality:** Locates relevant documents based on user input (e.g., keywords or example documents, like "database systems").
- **Scope:** Can be used on textual descriptions provided with non-textual data (e.g., images).
- **Example:** Web search engines are the most familiar example of Information Retrieval (IR) systems.

### Differences from Database Systems
- **Updates:** IR systems don't deal with transactional updates (including concurrency control and recovery).
- **Structure:** Database systems deal with structured data with schemas defining data organization.
- **Querying Issues:** IR systems handle approximate searching by keywords and ranking of retrieved answers by the estimated degree of relevance, which are generally not addressed by database systems.

## 2. Keyword Search
- **Full Text Retrieval:** All words in each document are considered keywords. The word "term" is used to refer to the words in a document.
- **Query Expressions:** Typically formed using keywords and logical connectives (`AND`, `OR`, `NOT`). `AND`s are implicit even if not explicitly specified.
- **Relevance Ranking:** Critical for retrieving documents. Based on factors such as:
  - **Term Frequency:** Frequency of occurrence of a query keyword in a document.
  - **Inverse Document Frequency:** How many documents the query keyword occurs in (fewer documents means more importance to the keyword).
  - **Hyperlinks:** More links to a document imply the document is more important.

## 3. Relevance Ranking Using Terms

![Relevance Ranking Using Terms](../images/ch31_slides/slide_006.png)
### TF-IDF Ranking (Term Frequency / Inverse Document Frequency)
Let:
- $n(d)$ = number of terms in the document $d$
- $n(d, t)$ = number of occurrences of term $t$ in the document $d$

**Relevance of a document $d$ to a term $t$ (TF):**
$$TF(d, t) = \log\left(1 + \frac{n(d, t)}{n(d)}\right)$$
*Note: The log factor avoids giving excessive weight to frequent terms.*

**Relevance of document $d$ to query $Q$:**
$$r(d, Q) = \sum_{t \in Q} \frac{TF(d, t)}{n(t)}$$
*(Note: $n(t)$ here represents document frequency - the number of documents containing term $t$. Dividing by $n(t)$ serves as the Inverse Document Frequency factor)*

### Enhancements to Relevance Ranking
Most systems add the following to the base TF-IDF model:
- **Location Weighting:** Words occurring in the title, author list, section headings, etc., are given greater importance.
- **Positional Weighting:** Words whose first occurrence is late in the document are given lower importance.
- **Stop Words:** Very common words (e.g., "a", "an", "the", "it") are eliminated.
- **Proximity:** If query keywords occur close together in the document, it receives higher importance than if they occur far apart.
- **Result Ordering:** Documents are returned in decreasing order of relevance score. Usually, only the top few documents are returned.

## 4. Similarity Based Retrieval
- Retrieves documents similar to a given document based on common words.
- Example: Find $k$ terms in document $A$ with the highest $\frac{TF(d, t)}{n(t)}$ and use these terms to find the relevance of other documents.
- **Relevance Feedback:** Used to refine the answer set for a keyword query. The user selects relevant documents from the initial retrieval, and the system finds other similar documents.

### Vector Space Model
- Defines an $n$-dimensional space, where $n$ is the number of words in the document set.
- **Vector for document $d$:** Goes from the origin to a point whose $i$-th coordinate is $\frac{TF(d, t_i)}{n(t_i)}$.
- **Similarity Measure:** The cosine of the angle between the vectors of two documents is used to measure their similarity.

## 5. Relevance Using Hyperlinks
- Using only term frequencies can result in an enormous number of relevant documents and makes "spamming" easy (e.g., repeatedly adding a keyword to boost ranking).
- **Idea:** Use the popularity of a website to rank pages that match given keywords.
- **Solution:** Use the number of hyperlinks pointing to a site as a measure of its popularity or prestige.
  - Count only one hyperlink from each site.
  - The popularity measure applies to the site, not just individual pages.
- **Challenges:** Most hyperlinks point to the root of a site, and defining a "site" is difficult (e.g., `cs.yale.edu` contains many unrelated pages of varying popularity).

### PageRank Mechanism
- When computing prestige, give more weight to links from sites that themselves have higher prestige.
- Since the definition is circular, it is modeled as a system of simultaneous linear equations to be solved. This idea forms the basis of the **Google PageRank** ranking mechanism.
- Connections exist to social networking theories that rank the prestige of people (e.g., knowing multiple prestigious people increases your own prestige).

### Hub and Authority Based Ranking
- **Hub:** A page that stores links to many pages on a topic.
- **Authority:** A page that contains actual information on a topic.
- **Hub Prestige:** Based on the prestige of authorities it points to.
- **Authority Prestige:** Based on the prestige of hubs that point to it.
- **Resolution:** These definitions are also cyclic and are solved using linear equations. Authority prestige is used when ranking answers to a query.

## 6. Synonyms, Homonyms, and Ontologies
### Synonyms and Homonyms
- **Synonyms:** Different words with the same meaning (e.g., "repair" and "maintenance"). The system can automatically extend queries using logical `OR` (e.g., `motorcycle AND (repair OR maintenance)`).
- **Homonyms:** Words with multiple meanings (e.g., "object" as a noun vs. a verb). Meanings can sometimes be disambiguated from context.
- **Challenges:** Extending queries automatically can be problematic without understanding the intended meaning or verifying with the user, as synonyms may also have alternative meanings.

### Concept-Based Querying

![Concept-Based Querying](../images/ch31_slides/slide_013.png)
- Determines the concept a word represents from context.
- **Ontologies:** Hierarchical structures showing relationships between concepts (e.g., the ISA relationship in the E-R model).
  - Used to standardize terminology in specific fields.
  - Can link multiple languages.
  - Serves as the foundation of the Semantic Web.

## 7. Indexing of Documents
- An **inverted index** maps each keyword $K_i$ to a set of documents $S_i$ that contain the keyword (identified by document identifiers).
- The index may also record:
  - Keyword locations within the document (for proximity-based ranking).
  - Occurrence counts (to compute Term Frequency).
- **Operations:**
  - `AND` operation: Intersection $S_1 \cap S_2 \cap \dots \cap S_n$. Finds documents that contain all of $K_1, K_2, \dots, K_n$.
  - `OR` operation: Union $S_1 \cup S_2 \cup \dots \cup S_n$. Finds documents that contain at least one of $K_1, K_2, \dots, K_n$.
  - `NOT` operation: Implemented efficiently via merging of sorted lists.
- Each $S_i$ is kept sorted to allow efficient intersection and union by merging sorted lists.

## 8. Measuring Retrieval Effectiveness

![Measuring Retrieval Effectiveness](../images/ch31_slides/slide_016.png)
- IR systems use index structures supporting approximate retrieval to save space. This can result in:
  - **False Negative (False Drop):** Relevant documents not retrieved.
  - **False Positive:** Irrelevant documents retrieved.
  - *Note:* Good indexes should not permit any false drops, but may permit a few false positives.
- **Performance Metrics:**
  - **Precision:** The percentage of retrieved documents that are relevant to the query.
  - **Recall:** The percentage of documents relevant to the query that were actually retrieved.
- **Tradeoff:** Increasing recall by retrieving more documents generally reduces precision (more irrelevant documents are fetched).
- **Effectiveness Measures:** Recall as a function of the number of documents fetched, or precision as a function of recall.
  - Example: "Precision of 75% at recall of 50%, and 60% at a recall of 75%".
- **Challenge:** Determining which documents are *actually* relevant.

## 9. Web Search Engines
- **Web Crawlers:** Programs that locate and gather information on the Web by recursively following hyperlinks from a seed set of documents.
  - Fetched documents are handed to an indexing system and either discarded or cached.
  - Crawling the entire Web takes a very large amount of time (months for a single crawl); search engines typically cover only a portion.
- **Parallel Processing:**
  - Crawling is done by multiple parallel processes on multiple machines.
  - Links to be crawled are stored in a database, and new links are appended for later crawling.
  - The indexing process creates a *new* copy of the index rather than modifying the old one. The old index serves queries until the new index is complete.
  - Queries are routed to multiple machines for load balancing, with indices often kept in memory.

## 10. Information Retrieval and Structured Data
- Originally, IR systems treated documents merely as collections of words.
- **Information Extraction Systems:** Infer structure from documents (e.g., extracting house attributes from an ad, or topics and people named from a news article).
- **Data Storage:** Relations or XML structures are used to store extracted data.
- **Question Answering Systems:** Seek connections among the extracted data to answer complex queries.

## 11. Directories
- Storing related documents together in a library facilitates browsing.
- Browsing is aided by a **classification system** organizing related documents hierarchically (Classification Hierarchy).
![A Classification Hierarchy For A Library System](../images/ch31_slides/slide_021.png)

- **Classification DAG:** Since physical location is not important in IR systems, a document can reside in multiple places in the hierarchy, forming a Directed Acyclic Graph (DAG).
![A Classification DAG For A Library](../images/ch31_slides/slide_023.png)

- **Web Directories:** Classification directories on Web pages (e.g., Yahoo! Directory, Open Directory project).
  - Issues include determining the directory hierarchy and categorizing documents.
  - Categorization can be manual or automated based on term similarity.
