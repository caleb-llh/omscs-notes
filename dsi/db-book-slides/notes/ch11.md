# Chapter 11: Data Analytics

## Overview
- **Data Analytics:** The processing of data to infer patterns, correlations, or models for prediction.
- Primarily used to make business decisions:
  - Per individual customer (e.g., product suggestions).
  - Across all customers (e.g., manufacturing/stock quantities).
- **Common Steps in Data Analytics:**
  1. **Gather Data:** Bring data from multiple sources into one location. 
     - Data often needs to be extracted, transformed to a common schema, and loaded (ETL: Extract-Transform-Load, or ELT: Extract-Load-Transform).
  2. **Generate Aggregates & Reports:** Create summaries, graphical dashboards, and interactive queries using Online Analytical Processing (OLAP) and statistical tools (R/SAS/SPSS).
  3. **Build Predictive Models:** Use machine learning techniques to find patterns and make predictions for decision-making (e.g., loan default prediction, sales forecasting, targeting customers).
- **Terminology:**
  - **Machine Learning (ML):** Key to finding patterns and making predictions.
  - **Data Mining:** Extending ML techniques to run on very large datasets.
  - **Business Intelligence (BI):** Synonym for data analytics.
  - **Decision Support:** Focuses on reporting and aggregation.

## Data Warehousing
- **Motivation:** Corporate decision-making requires a unified view of historical and current data, while operational data sources often only store current data.
- **Data Warehouse:** A repository of information gathered from multiple sources, stored under a unified schema, at a single site.
  - Simplifies querying and permits study of historical trends.
  - Shifts decision-support query load away from transaction processing (OLTP) systems.

### Design Issues
- **When and How to Gather Data:**
  - **Source-Driven Architecture:** Data sources continuously or periodically transmit new information to the warehouse.
  - **Destination-Driven Architecture:** The warehouse periodically requests new information.
  - Synchronous replication (e.g., two-phase commit) is often too expensive; it is usually acceptable to have slightly out-of-date data.
- **Schema Integration & Data Transformation:**
  - **Data Cleansing:** Correcting mistakes (e.g., misspellings) and merging/purging duplicates.
- **View Maintenance:** The warehouse schema may act as a materialized view of the data sources.
- **Summarization:** Raw data may be too large, so aggregate values (totals/subtotals) often suffice.

### Multidimensional Data and Warehouse Schemas
![Data Warehouse Schema](../images/ch11_slides/slide_013.png)
- Data is usually divided into:
  - **Fact Tables:** Large tables containing measure attributes (e.g., `sales(item_id, store_id, customer_id, date, quantity, price)`).
    - **Measure Attributes:** Values that can be aggregated (e.g., quantity, price).
  - **Dimension Tables:** Relatively small tables storing extra information (e.g., store details, item details).
    - **Dimension Attributes:** Dimensions on which measures are viewed (e.g., color, size). Usually referenced by foreign keys.
- **Schemas:**
  - **Star Schema:** A single fact table joined with multiple dimension tables.
  - **Snowflake Schema:** Multiple levels of dimension tables.
- **Data Lakes:** Repositories allowing data to be stored in multiple formats without upfront schema integration. Less upfront effort, but more effort during querying.

### Database Support for Data Warehouses
- Data is typically append-only (rarely updated), avoiding concurrency control overheads.
- **Column-Oriented Storage:** Arrays of column values are compressed, reducing storage, I/O, and memory costs. Queries fetch only needed attributes.
- **Parallel Storage & Query Processing:** Use distributed file systems, MapReduce, Hive, etc.

## Online Analytical Processing (OLAP)
- **OLAP:** Interactive analysis allowing data to be summarized and viewed in different ways online (with negligible delay).
- **Cross-Tabulation (Pivot-Table):** 
  - Values for one dimension attribute form row headers, another forms column headers. 
  - Cells contain aggregates of the dimension attributes.
- **Data Cube:** A multidimensional generalization of a cross-tab.
![Data Cube](../images/ch11_slides/slide_020.png)

### OLAP Operations
- **Pivoting:** Changing the dimensions used in a cross-tab.
- **Slicing (and Dicing):** Creating a cross-tab for fixed values only (e.g., color = white and size = small).
- **Rollup:** Moving from finer-granularity data to a coarser granularity (e.g., day → month → year).
- **Drill Down:** Moving from coarser-granularity to finer-granularity data.
- **Hierarchies on Dimensions:** Allowing dimensions to be viewed at different levels of detail (e.g., `item_name` → `category`).

### OLAP in SQL
- The `PIVOT` operation can rotate rows into columns.
- The `CUBE` operation computes the union of `GROUP BY`'s on every subset of the specified attributes.
- The `ROLLUP` construct generates the union on every prefix of the specified list of attributes.
- The `GROUPING()` function and `DECODE()` can handle null values introduced by `CUBE` and `ROLLUP`.
- Multiple rollups/cubes can be combined, and `GROUPING SETS` can define exact groupings.

### OLAP Implementation
- **MOLAP (Multidimensional OLAP):** Uses multidimensional arrays in memory.
- **ROLAP (Relational OLAP):** Uses relational database features.
- **HOLAP (Hybrid OLAP):** Stores summaries in memory and base data/other summaries in a relational database.
- **Precomputation:** Early systems precomputed all aggregates ($2^n$ combinations). Modern systems precompute some and compute others on demand (e.g., aggregate by `(item_name, color)` derived from `(item_name, color, size)`).

### Reporting and Visualization
- **Reporting Tools:** Create formatted tabular/graphical reports (e.g., SQL Server Reporting Services, Crystal Reports).
- **Data Visualization Tools:** Create interactive visualizations (e.g., Tableau, Plotly, Google Charts).

## Data Mining
- **Data Mining:** The semi-automatic process of analyzing large databases to find useful patterns (part of Knowledge Discovery in Databases - KDD).

### Types of Data Mining Tasks
1. **Prediction Based on Past History:**
   - **Classification:** Predicting which discrete class an item belongs to (e.g., credit risk).
   - **Regression:** Predicting a continuous function result for a new parameter value.
2. **Descriptive Patterns:**
   - **Associations:** Finding items bought together by similar customers (can help detect causation).
   - **Clusters:** Grouping data into clusters (e.g., epidemic detection around a contaminated well).

### Classifiers
- **Decision Tree Classifiers:** Internal nodes partition data based on attribute conditions. Leaf nodes predict a class. Traverse from root to leaf to make predictions.
![Decision Trees](../images/ch11_slides/slide_040.png)
- **Bayesian Classifiers:** Use Bayes' theorem to find probability of a class given an instance.
  - **Naïve Bayesian Classifiers:** Assume attributes have independent distributions to simplify calculations.
- **Support Vector Machines (SVM):** Find a maximum margin separator (line, plane, or curve using kernel functions) between classes. N-ary classification uses N binary classifications.
![Support Vector Machine Classifiers](../images/ch11_slides/slide_043.png)
- **Neural Network Classifiers:** Multiple layers of nodes. Nodes combine inputs using weights (learnt during training via **backpropagation**) and non-linear functions (e.g., sigmoid).
  - **Deep Learning:** Training deep neural networks (many layers) on large datasets (e.g., Convolutional Neural Networks for images).

### Regression
- Predicts a value rather than a class.
- **Linear Regression:** Finding a linear polynomial (coefficients) that best fits the data. Also known broadly as curve fitting.

### Association Rules
- Finding associations between items (e.g., `bread ⇒ milk`).
- **Support:** Fraction of the population that satisfies both the antecedent and consequent.
- **Confidence:** How often the consequent is true when the antecedent is true.
- **A Priori Technique:** An algorithm to find frequent itemsets efficiently by eliminating sets whose subsets lack sufficient support.
- **Other Associations:** Positive/negative correlations and temporal sequence deviations (e.g., sales drops not predicted by past patterns).

### Clustering
- Grouping similar points based on distance metrics (e.g., minimizing average distance to a centroid).
- **Hierarchical Clustering:** 
  - **Agglomerative:** Build small clusters and merge them.
  - **Divisive:** Start with one large cluster and repeatedly break it.
- **Birch Algorithm:** Designed for large datasets using an in-memory R-tree to dynamically insert and merge clusters.
- **Collaborative Filtering:** Uses repeated clustering of users and items to make recommendations (e.g., movie suggestions).

### Other Types of Mining
- **Text Mining:** Application of data mining to documents.
- **Sentiment Analysis:** Predicting positive/negative sentiment.
- **Information Extraction:** Creating structured info from unstructured text.
- **Entity Recognition and Disambiguation:** Identifying specific entities in text (e.g., distinguishing between different people with the same name).
- **Knowledge Graphs:** Constructed by extracting information from various sources (e.g., Wikipedia).

## Appendix: Decision Tree Splits Details
- **Purity Measures for Splits:**
  - **Gini Measure:** $1 - \sum p_i^2$ (0 if all instances are in one class).
  - **Entropy Measure:** $-\sum p_i \log_2(p_i)$.
- **Information Gain:** Difference between parent purity and weighted child purity.
- **Finding Best Splits:** 
  - Categorical: Multi-way split or binary split.
  - Continuous: Sort values and try binary splits at each threshold, picking the one with the best Information Gain Ratio.
